# pipe-io v0.8.0 - Examples and guide

**Date:** 2026-05-19
**Compare:** `v0.7.0...v0.8.0`

## Headline

Bridge release between the feature-completion arc (`0.5`-`0.7`)
and the pre-1.0 stabilization line (`0.9`). No public API changes
from `0.7.0`. Adds eight runnable examples and a user guide so
the locked surface is approachable from outside the reference
docs.

## What changed since `v0.7.0`

### New - `examples/`

| Example         | Demonstrates                                                  |
|-----------------|---------------------------------------------------------------|
| `basic`         | Minimal map / filter pipeline collecting into `VecSink`.      |
| `batching`      | `BatchPolicy::new().max_items(N)` count-triggered batching.   |
| `windowing`     | Tumbling window with a deterministic scripted clock.          |
| `dead_letter`   | `ErrorPolicy::DeadLetter` + `.dead_letter(sink)` routing.     |
| `threaded`      | `Pipeline::run_threaded()` on a spawned worker thread.        |
| `custom_driver` | Implementing the `Driver` trait with timing instrumentation.  |
| `custom_source` | Implementing `Source` for a stateful Fibonacci producer.      |
| `etl`           | Multi-stage CSV ETL with `Continue` policy, enrichment, and a |
|                 | batching sink that prints per-row.                            |

Run any example with `cargo run --example <name>`. Every example
has been verified to build clean under
`cargo clippy --all-targets --all-features -- -D warnings` and
to produce the expected output end-to-end.

### New - `docs/GUIDE.md`

11-section walkthrough covering:

1. Mental model (Source / Stage / Sink).
2. Building your first pipeline.
3. The closure-adapter cheat sheet.
4. Implementing custom stages with the `Stage` trait.
5. Batching primer (`BatchPolicy` triggers).
6. Windowing primer (Tumbling / Sliding / Session).
7. Error policies (`FailFast` / `Continue` / `DeadLetter`).
8. Dead-letter routing.
9. Picking a driver (sync / threaded / custom).
10. Implementing a custom `Driver`, `Source`, or `Sink`.
11. Pitfalls (Clone requirement for sliding windows, no background
    timer, std-only `VecSink`, source error semantics, etc.).

Cross-linked from `README.md`, `docs/README.md`, and `docs/API.md`.

## Migration

### From `v0.7.0`

No source changes required. The crate's public API is unchanged.
Existing consumers can upgrade without recompiling against new
signatures.

To pull in the new examples for inspection or local testing:

```text
git pull
cargo run --example basic
cargo run --example etl
```

To read the guide offline, browse [`docs/GUIDE.md`](../GUIDE.md)
in the repository, or view it on the GitHub web UI.

## Stability commitment

Unchanged. `0.x.y` releases are not API-stable; API freeze begins
at `1.0.0`. After `0.8.0`, the path to `1.0.0` is:

1. `v0.9.0` - Pre-1.0 stabilization (property tests, fuzz
   targets, `cargo-semver-checks` in CI, documentation audit,
   migration guide).
2. `v1.0.0-rc.1` - API frozen, 14-day soak per `ROADMAP.md`.
3. `v1.0.0` - Stable.

`PipelineBuilder::buffer(capacity)` remains roadmap material and
is not blocked on any of the steps above.

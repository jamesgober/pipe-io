# pipe-io v0.9.0 - Pre-1.0 stabilization

**Date:** 2026-05-19
**Compare:** `v0.8.0...v0.9.0`

## Headline

Pre-1.0 stabilization. No public API changes. Adds the hardening
infrastructure that gates the path to `1.0.0`:

- **Property tests** under `tests/property.rs` (11 tests, std-only,
  `proptest` dev-dependency).
- **Fuzz harnesses** under `fuzz/` (four `cargo-fuzz` targets,
  excluded from the main workspace).
- **`cargo-semver-checks`** CI job (advisory until a `1.0.0`
  baseline lands on crates.io; will flip to a hard gate at
  release).
- **Documentation audit** - every public item carries rustdoc,
  doc-link checks pass under
  `RUSTDOCFLAGS="-D warnings -D rustdoc::broken-intra-doc-links"`.
- **Migration guide** at `docs/MIGRATION.md` covering every
  release in the `0.x` line.

Existing source compiles identically. Consumers can upgrade
without touching their code.

## What changed since `v0.8.0`

### New - Property tests (`tests/property.rs`)

Eleven `proptest`-based invariant tests covering:

| Invariant                                            | Test                                |
|------------------------------------------------------|-------------------------------------|
| `map` preserves length                               | `map_preserves_length`              |
| `filter` admits only items satisfying the predicate  | `filter_admits_only_satisfying_items` |
| Trivial pipelines preserve input order               | `pipeline_preserves_order`          |
| Batching is lossless                                 | `batching_is_lossless`              |
| Batches respect `max_items`                          | `batches_respect_max_items`         |
| Tumbling windows are lossless                        | `tumbling_windowing_is_lossless`    |
| Window time bounds satisfy `start <= end`            | `tumbling_window_times_are_monotonic` |
| `Continue` policy never surfaces run-level errors    | `continue_policy_swallows_errors`   |
| `DeadLetter` partitions items between sinks          | `dead_letter_partitions_items`      |
| `run` and `run_with(SyncDriver)` agree               | `run_and_run_with_sync_agree`       |
| `run_threaded` agrees with `run`                     | `run_threaded_agrees_with_sync`     |

All 11 pass under `cargo test --all-features`. The dev-dependency
added is `proptest = "1"`; the published crate ships zero runtime
dependencies.

### New - Fuzz harnesses (`fuzz/`)

Four `cargo-fuzz` targets:

| Target              | Invariant under test                                            |
|---------------------|-----------------------------------------------------------------|
| `batching_count`    | Count-triggered batching is lossless for arbitrary input bytes. |
| `batching_bytes`    | Byte-triggered batching is lossless for arbitrary string items. |
| `try_map_continue`  | `ErrorPolicy::Continue` never surfaces a run-level error.       |
| `window_tumbling`   | Tumbling windows preserve every input item under a fake clock.  |

The fuzz crate is excluded from the main workspace
(`workspace.exclude = ["fuzz"]`) and is not published. Requires
nightly Rust and `cargo install cargo-fuzz` to run.

### New - `cargo-semver-checks` CI job

The CI matrix gains a `semver-checks` job that runs
`cargo-semver-checks check-release` against the main branch.
The job is advisory (`|| true`) for the `0.x` line; the suffix
will be removed when the `1.0.0` baseline ships, making
breaking-change detection a hard merge gate.

### New - Migration guide (`docs/MIGRATION.md`)

Per-version upgrade notes covering every step from `v0.1.0` to
`v0.9.0`. The guide also documents the binding stability
commitment at `1.0.0` (patch / minor / major rules from
`REPS.md` section 8). Linked from `docs/README.md`.

### Changed - Documentation audit

The audit pass confirms:

- Every public item has a rustdoc block.
- `# Errors`, `# Panics`, and `# Example` sections are present
  where applicable.
- `cargo doc --all-features --no-deps` builds clean under
  `RUSTDOCFLAGS="-D warnings -D rustdoc::broken-intra-doc-links"`.
- `docs/API.md`, `docs/GUIDE.md`, `docs/BENCH.md`,
  `docs/MIGRATION.md`, `README.md`, and `REPS.md` cross-link
  consistently.
- The banned-word and em-dash scan continues to return zero hits
  across all shipping paths.

## Migration

### From `v0.8.0`

No breaking changes. The release is hardening and documentation
only. Existing source compiles identically.

If you have a CI pipeline that builds and tests `pipe-io` as part
of an integration matrix, note that:

- `cargo test --all-features` now runs 84 tests (up from 73).
- The new `proptest` dev-dependency adds a small compile-time
  cost when building the test binary.
- The published crate is unchanged in its dependency footprint
  (still zero runtime dependencies).

To run the new property tests against a custom invariant:

```rust
use proptest::prelude::*;

proptest! {
    #[test]
    fn my_invariant(items in proptest::collection::vec(any::<i32>(), 0..32)) {
        // ... build pipeline, assert invariant ...
    }
}
```

See [`tests/property.rs`](../../tests/property.rs) for the full
set used in-tree.

To run the fuzz harnesses:

```text
cd fuzz
cargo +nightly fuzz run batching_count
```

See [`fuzz/README.md`](../../fuzz/README.md) for the per-target
list.

## Stability commitment

`0.9.0` is the last `0.x` release before `1.0.0-rc.1`. The
public surface in `REPS.md` section 4 is locked; any change
between `0.9.0` and `1.0.0` is a bug fix only. The locked
`1.0.0` rules will apply:

- **Patch (`1.0.x`)** - bug fixes, doc improvements, internal
  performance work, test additions. No new public items.
- **Minor (`1.x.0`)** - pure additions to the public surface,
  new opt-in features, new variants on enums reserved for
  growth, MSRV bumps.
- **Major (`2.0.0`)** - removes, renames, or signature changes
  of public symbols, or non-opt-in runtime dependency additions.

The `cargo-semver-checks` CI job will be promoted from advisory
to a hard gate when `1.0.0` ships.

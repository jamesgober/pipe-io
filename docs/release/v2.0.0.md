# pipe-io v2.0.0 - Guaranteed Teardown, Real Backpressure, Steppable Pipelines

**Date:** 2026-10-13
**Compare:** `v1.0.0...v2.0.0`

## Headline

**`2.0` makes pipe-io's promises true.** A pipeline now flushes and
closes its sink, dead-letter sink, and source on every exit path,
including errors and panics; a failing stage `flush` no longer loses
downstream data; bad configuration is a typed error instead of a panic
or a hang; `buffer(capacity)` gives real bounded, backpressured edges
with one thread per segment; and `Pipeline::step` lets tokio, rayon, or
any executor drive a pipeline. The error model now supports
`Error::source()` and downcasting.

This is a **major release**: the fixes change behaviour users can
observe, the MSRV moves to 1.85, and error types must implement
`std::error::Error`. Most code needs one line per custom error type.
See [Migration](#migration).

Behind the line: the 2026-10-13 deep audit scored `1.0.0` at 65/100 and
found a silent data-loss bug, hangs and panics reachable from the
builder, no teardown on error paths, and documentation that claimed
bounded buffers and pluggable async drivers that did not exist. Every
finding from that audit, and the ten still open from the May audit, is
closed or recorded with a reason in the update log. An independent
re-audit of the `2.0.0` candidate then found four medium issues in the
new features (keyed windows, `buffer` edges, threaded teardown order)
and several small ones; they were fixed before the release (see
[Fixed before release](#fixed-before-release---the-200-re-audit)).

## Breaking changes

| Change | What to do |
|--------|------------|
| MSRV 1.85, edition 2024 | Use Rust 1.85 or newer. |
| `StageError` requires `Into<Box<dyn Error + Send + Sync>>` | Add `impl std::error::Error for YourError {}`; `&str` and `String` still work. |
| Builder panics and hangs became `Error::Config` | Handle `Error::Config`, or call `try_sink` and handle `ConfigError`. |
| `DeadLetter` without a dead-letter sink is a config error | Install `.dead_letter(sink)` or use `Continue`. |
| `max_items(0)`, zero durations, `slide > size` rejected | Use valid limits. |
| `RunStats`, `ErrorPolicy`, `WindowPolicy`, `EmitError`, `ChannelSinkError` are `#[non_exhaustive]` | Add wildcard arms; build `RunStats` from `Default`. |
| `EmitError::WouldBlock`, `Error::Buffer`, `BufferErrorKind` removed | Remove matches on them (never produced). |
| Threaded panics are re-raised (were `Error::Cancelled`) | Catch the panic if you relied on the error. |
| Windows skip empty windows; tumbling flush reports the nominal end; sliding windows include the first item in every covering window | Check window consumers that counted empty windows or read `end()` of the last window. |
| `ReaderSource` errors are `ReaderError`; 1 MiB default line limit | Match `ReaderError`; raise `.max_line_len(n)` if needed. |
| Builder type parameter bound is `Assemble` (sealed) | Name it as `impl Assemble<T, S::Item>` in helpers; it cannot be implemented or called. |

Full details: [`docs/MIGRATION.md`](../MIGRATION.md#v100---v200).

## What changed since `v1.0.0`

### Fixed - flush always reaches the sink (PIPE-001)

A custom stage whose `flush` failed under `Continue` or `DeadLetter`
stopped the flush: every batch or window buffered downstream, and the
sink's own flush, were dropped while `run` returned `Ok`. The failure is
now recorded by the stage's policy and the flush continues to every
later stage and the sink. Regression test:
`tests/regressions.rs::pipe_001_flush_error_does_not_lose_downstream_data`.

### Fixed - teardown on every exit path (PIPE-007)

On any error the sink, the dead-letter sink, and the source were never
flushed or closed. Now the run tears down on success, error,
cancellation, panic, and when a stepped pipeline is dropped. Teardown is
RAII: the object owning the source and the chain does it in `Drop`, with
each user `flush`/`close` contained by `catch_unwind` so a second panic
cannot abort. The first error is returned; later ones go to the observer
as `Event::TeardownError`.

### Fixed - configuration can no longer hang or panic (PIPE-002..006, PIPE-016)

Zero window sizes looped forever, `Duration::MAX` overflowed `Instant`,
`max_items(usize::MAX)` panicked, large `max_items` reserved memory per
batch, the byte counter could overflow, and `slide > size` dropped
items silently. Every builder setting is now validated into a typed
`ConfigError` (reported by `run`, or immediately by `try_sink`); all
time and size arithmetic is checked or saturating; batches reserve at
most 1024 slots up front.

### Fixed - no flood of empty windows (PIPE-003)

A quiet gap emitted one window per elapsed interval (a million empty
windows for one second of 1 µs windows). Window boundaries now skip
forward arithmetically and only non-empty windows are emitted.

### Added - bounded edges and a real threaded driver (PIPE-008)

`.buffer(capacity)` splits a pipeline. Under `run_threaded` each segment
runs on its own thread and edges are bounded channels: a full edge
blocks the upstream thread, so a slow sink slows the source and memory
between stages is bounded. An edge allocates only for the items queued
in it (nothing is reserved for the whole capacity), and capacities above
2^20 are a configuration error. Ordering is preserved; the first error
wins and tears down both directions; a panic is re-raised with its
payload after every thread is joined; cancellation drains gracefully;
the source is closed only after the sink has flushed and closed. Under
`run` an edge is a direct call.

Window and batch buffers are bounded or documented: `WindowSpec` adds a
per-window `max_items` and a per-stage `max_keys`; the batch bounds are
spelled out in the `batch` module docs and `docs/ARCHITECTURE.md`.

### Added - steppable pipelines and external drivers (PIPE-009)

`Pipeline::step`, `tick`, `finish`, and `stats` let any executor drive a
pipeline. New examples: `tokio_driver` (runs and cancels pipelines from
a tokio runtime via `spawn_blocking`, with a `Driver` implementation for
sync callers), `rayon_driver` (one pipeline or many partitions on a
bounded pool), and a rewritten `custom_driver`.

### Added - quiet streams (PIPE-017)

`.idle_tick(interval)` makes age-triggered batches and windows fire
when the source is quiet. Sources opt in through
`Source::pull_timeout` (`ChannelSource` does); stages through
`Stage::tick`. Batching and windowing take an explicit `Clock`
(`ManualClock` for tests).

### Added - operations

`Pipeline::cancel_handle` (graceful cancellation), `.observe(...)` with
`Event`s for start, stage errors, retries, dead letters, idle ticks,
teardown errors, and finish, and `RunStats` counters for items in and
out, errors, dead letters, and retries.

### Added - error handling

`try_map_ref` (the failing item rides along in `StageFailure::input`),
`try_map_retry` with `RetryPolicy` (fixed or exponential backoff,
optional jitter), `Error::source()`, `inner`, `into_inner`,
`downcast_ref`, and `source_id` for naming the source.

### Added - windows and adapters

Per-key windows (`window_by_key`): every item, of any key, and every
idle tick close the expired windows of all keys, so a quiet key's window
is emitted on time on a busy stream, and the `max_keys` eviction is
O(1). Window constructors
(`WindowPolicy::tumbling` / `sliding` / `session`), `TeeSink`,
`ChainSource`, `ByteLinesSource`, `Debug` on every public type, and
conversions on `Batch` and `Window`.

### Security - bounded line reading (PIPE-010)

`ReaderSource` read a line of any length into memory. It now caps a
line at `max_line_len` (1 MiB by default) with an overflow policy
(`Error`, `Skip`, `Truncate`) and optional lossy UTF-8.
`ByteLinesSource` reads raw byte lines with the same limits. A fuzz
target (`reader_lines`) checks both readers on arbitrary input.

### Fixed before release - the 2.0.0 re-audit

An independent re-audit of the release candidate (`97a5640`) scored it
82/100 and found these problems in the new features. All are fixed, each
with a regression test that fails on the candidate (`tests/reaudit.rs`,
`tests/edge_memory.rs`, `tests/threaded_stress.rs`):

- **R01 (keyed windows on busy streams).** A key's window closed only
  when that key sent again, so a quiet tenant's window could be emitted
  minutes late (300 s in the audit's probe). Keyed windows now keep a
  min-heap of per-key deadlines: every item and tick closes every
  expired window, in deadline order (deterministic, where ticks used to
  emit in hash order).
- **R02 (quadratic eviction).** Reaching `max_keys` scanned every key
  for each new key: 91 µs per item at 10,000 keys. Eviction is now O(1)
  (an LRU list over the key slab): about 0.2 µs per item at any limit
  (see Performance).
- **R03 (`buffer` capacity).** The capacity was not validated and every
  slot was reserved up front; `buffer(1 << 27)` took seconds and a huge
  value aborted the process. The edge now allocates only for queued
  items (a counting-allocator test: 4.3 GB before, under 16 MB after, for
  `buffer(1 << 20)` with 4 KiB items), and capacities above 2^20 are
  `ConfigErrorKind::LimitTooLarge`.
- **R04 (threaded teardown order).** `run_threaded` closed the source
  while the sink was still writing. The source thread now waits for
  every downstream segment before `Source::close`, matching the
  documented order.
- **R05.** Retry backoff ignored cancellation; it now stops waiting
  within about 10 ms.
- **R06.** `ReaderSource::with_capacity(0, ..)` reported an empty
  stream; the buffer is now at least one byte.
- **R07.** A failing sink `flush` was called twice and a panicking one
  prevented `close`. Every lifecycle call now runs exactly once, and
  teardown resumes after a panicking call.
- **R08.** A stepped pipeline kept running after a caught panic, losing
  the item in flight; it is now poisoned and the next call fails with
  `Error::Driver` after tearing down.
- **R09, R10, R13.** Documented that a blocked source delays noticing a
  downstream failure under `run_threaded` (use `idle_tick`); the
  performance claims are restated (see below); `ChainSource` respects
  its timeout across the switch; `TeeSink` keeps both errors when both
  halves fail; batches reserve at most 64 KiB up front; a panicking
  observer during teardown is contained.
- **R11.** `Assemble` is sealed and the execution internals are private,
  so the calling convention can evolve without a major release.
- **R12.** Kept `#![deny(warnings)]` at the crate root, as the portfolio REPS
  requires. Cargo caps lints for dependencies, so it never breaks a
  downstream build.

### Changed - housekeeping

- MSRV 1.85, edition 2024, the portfolio lint block at the crate root,
  no `unwrap`/`expect`/`unreachable!` in library code, poisoned locks
  recovered instead of panicking.
- `rust-toolchain.toml` pins the local toolchain; every CI job sets
  `RUSTUP_TOOLCHAIN` explicitly, so stable jobs run current stable.
- `deny.toml` added; CI gained `cargo audit`, `cargo deny`, coverage
  (90% line gate), `--no-default-features` tests, `no_std` builds for
  `thumbv7em-none-eabihf` and `thumbv6m-none-eabi`, MSRV tests, and a
  60-second fuzz run per target; `actions/checkout@v7`.
- The README and the user guide are compiled as doctests; the docs gain
  `ARCHITECTURE.md` and `PLATFORM-NOTES.md`; the references to the
  unpublished `.dev/` directory are gone.

## Performance

Measured on an AMD Ryzen 9 9950X3D, Windows 11 Pro, rustc 1.99.0,
criterion 0.7, 100,000 items per iteration. `1.0.0` and `2.0.0` were
linked into one benchmark binary and run alternately (five rounds, high
priority, pinned cores) because the machine was under heavy unrelated
load. Medians, M items / s:

| Scenario | 1.0.0 | 2.0.0 | Change |
|----------|------:|------:|-------:|
| source -> null sink | 500 | 524 | +5% |
| source -> map -> sink | 257 | 383 | +49% |
| source -> map -> filter -> map -> sink | 180 | 274 | +53% |
| source -> filter(false) -> sink | 442 | 475 | +8% |
| source -> batch(100) -> sink | 135 | 149 | +11% |
| source -> try_map(ok) -> sink | 284 | 424 | +49% |
| source -> try_map(50% err, Continue) -> sink | 312 | 340 | +9% |
| `run_threaded`: source -> map -> sink | 144 | 188 | inconclusive (high variance) |

These numbers favour `2.0.0` more than an independent re-audit found:
its A/B run (nine rounds, 20 M items) measured the bare source -> null
sink path about 20-25% slower in `2.0.0` (1.8 versus 1.4 ns per item,
under 1 ns either way), map -> sink even, and map -> filter -> map
faster. The fair summary: multi-stage chains are faster, and the
simplest path is within about 0.5 ns per item.

Keyed windows with distinct keys (200,000 items, 1 h tumbling windows),
the release candidate versus the release, same binary, alternating,
ns per item (medians, machine at about 94% CPU from other work):

| `max_keys` | candidate | release | Speed-up |
|-----------:|----------:|--------:|---------:|
| none | 540 | 387 | 1.4x |
| 1,000 | 1,798 | 212 | 8.5x |
| 10,000 | 21,191 | 239 | 89x |
| 100,000 | 119,033 | 268 | 444x |

Edges (`run_threaded`, 2,000,000 items through one edge, ns per item):
`buffer(1024)` 27 (candidate 33), `buffer(64)` 36 (50), `buffer(16)` 71
(50), `buffer(1)` 373 (1,287), `buffer(0)` 360 (562). Capacity 16 is
the one case that got slower; use 64 or more for throughput. A tumbling
window with the system clock costs about 33 ns per item, dominated by
the clock read. Full tables and method: [`docs/BENCH.md`](../BENCH.md).

The speed-up comes from the per-item calling convention (control
operations as unit variants, sink-write counts returned through the
chain, boxed failures), which keeps every stage call's arguments and
result in registers. An intermediate build that added the run context
and counters without these changes was 10-20% slower than `1.0.0`.

## Migration

### From `v1.0.0`

1. Use Rust 1.85 or newer.
2. Implement `std::error::Error` for custom error types used by
   sources, stages, and sinks (`&'static str` and `String` still work).
3. Handle `Error::Config` (or call `try_sink`) where a pipeline used to
   panic on bad settings, and add `.dead_letter(sink)` wherever
   `ErrorPolicy::DeadLetter` is used.
4. Add wildcard arms when matching `ErrorPolicy`, `WindowPolicy`,
   `EmitError`, or `ChannelSinkError`; build `RunStats` from `Default`.
5. Review window consumers (no empty windows; nominal end on flush;
   sliding grid) and code that relied on `run_threaded` turning panics
   into `Error::Cancelled`.

Step-by-step notes with before/after code:
[`docs/MIGRATION.md`](../MIGRATION.md#v100---v200).

## Stability commitment

From `2.0.0` (full policy in [`REPS.md`](../../REPS.md) section 8):

- **Patch (`2.0.x`)** - bug fixes, documentation, internal performance
  work, tests.
- **Minor (`2.x.0`)** - additions, new opt-in features, new variants of
  `#[non_exhaustive]` enums and fields of `#[non_exhaustive]` structs.
- **Major (`3.0.0`)** - removals, renames, signature or behaviour
  changes, MSRV bumps.

`cargo-semver-checks` runs in CI on every pull request and push to
`main`. The execution internals are private and `Assemble` is sealed,
so they are not part of the API.

## What's next
